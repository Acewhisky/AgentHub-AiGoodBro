# 连接清单 · 0915v5

用 AiGoodBro 的「使用引导」完成一次所选工具配置，首次安装弹窗也是同一个入口。先勾选常用工具或「选择已安装工具」，点击「开始依次登录」。已读取到身份的普通账号直接复用，不新增固定身份、特殊中枢账号或重复环境。

| 工具 | 登录入口 | 返回后的证据 |
| --- | --- | --- |
| Codex | 应用添加独立账号或恢复已有账号，官方浏览器授权 | 独立目录中的账号身份；额度单独读取 |
| Claude Code | 已安装官方 `claude auth login` | 浏览器授权后检查账号；API 配置不等于订阅 |
| Gemini CLI | 官方交互界面 Google 登录或 API Key；`/auth` 可更换方式 | 读取当前方式的本地配置，API Key 不要求 Code Assist 订阅额度 |
| Kimi Code | 对应环境的官方 `kimi login` | 返回后读取同一环境 |
| OpenCode | 已保存服务商配置时直接打开；新增或更换时选择「添加或更新服务商」进入官方 `opencode auth login` | 每个服务商分别配置；OpenCode Go 额度不能代表所有服务商，不因额度未知要求重新输入 API |
| WorkBuddy | 选择真实使用的国内/国际桌面产品对应内置 CLI，输入 `/login` | 地区分别检查，不自动替换；无法读取身份时保留待核验 |
| Grok | 对应独立环境的官方 `grok login --oauth` | 授权返回后检查官方身份和额度 |
| ZCode | 打开正式 ZCode 桌面应用，在应用中登录 | 用户确认桌面已登录；Coding Plan 配置不是桌面身份凭据 |
| TRAE | 打开 TRAE SOLO 桌面应用 | 用户确认与可读取额度分开 |
| MiMo | 复用已安装工具的官方登录，当前仅读取已有配置 | 未接通自动登录时明确显示人工步骤 |

相对 0915v4：OpenCode 默认复用保存的服务商配置；只有明确添加或更换服务商才重新进入认证。继续保留当前登录配置自动检测与配套包完整性验证。

一次只处理一项官方授权。已保存凭据会自动检测（登录期间每两秒，返回应用时重查），不需要关闭终端；无法自动读取的桌面工具完成后点「我已在官方工具完成，检查并继续」；交互式 CLI 不要求退出整个终端。应用停止等待退出，但保留终端和原回执。失败或不确定时不要重复打开多个同平台登录窗口。未安装的工具先按官方说明安装，重新检测；用户不需要的取消选择或留到以后。

“本人已确认”是用户操作记录，不能冒充自动核验、额度正常或模型可调用。“已配置 API Key”“已保存登录凭据”仅证明本地配置存在；“已读到账号”来自现有适配器的身份结果，均不代表指定模型可用。没有权限、网络失败、额度未知、需要登录分别处理，不把全部失败归咎于登录失效。不要要求用户发送验证码、密钥、认证文件或终端完整输出。

完成工具清单后进入「准备运行环境」，检查 Python、Codex 与随包组件，再由用户安装或更新配套 Skill。沿用现有安装器的差异比较、受管文件备份和完整性验证，保留用户自己的 Skill 文档、账号策略、认证与全局配置。发现运行中的调度先查原任务，不靠安装或重新开启服务解决占用。安装前必须核对最终包的 CompanionSkill 文件覆盖安装器清单、CompanionHub 的文件和哈希齐全。Skill 文件匹配不代表 Hub 已启用；需要调度时才选工作目录开启服务。

后续调用沿用 [运行环境说明](runtime-setup.md) 的 plan → 预检与占用 → run → status/result。仅在用户授权实际任务后做对应提供商验证；登录引导不自动发送模型请求。非改动代码只对比差异，实际测试集中到新增或改动的入口；原生登录步骤可以由用户配合验收。
