# Grok CLI 调用 · 0911v1

适用：用户明确调用 Grok / grokcli，或能力评估选择 Grok 的已授权任务。2026-09-10 在原生 Grok CLI 1.0.25 验证了官方登录、模型可用性和真实文件任务；升级后重新核对相关帮助参数，不将这一版本现象推广到其他 CLI。

## 身份与环境

- 优先使用已发现的官方 Grok CLI，读取它自己的 `--version`、`--help` 和登录子命令帮助。官方登录由用户在 CLI / 浏览器完成；不复制 Codex 凭据，不代填验证码。
- 独立账号环境同时指定 `GROK_HOME` 和 `GROK_AUTH_PATH`，后者指向该环境的 auth.json；取消继承 XAI_API_KEY、GROK_API_KEY、GROK_OAUTH_TOKEN，避免服务商认证被环境变量覆盖。不要用全局 HOME 重定向代替供应商支持的隔离方式。
- 登录命令退出 0 不是全部证据。还要通过同一环境的官方账号接口或官方 CLI 已认证状态确认；额外额度为零、缺失订阅百分比和登录失败分别处理。网页显示订阅不证明 CLI 已登录。
- 账号和项目继续使用现有共享 Registry 的真实身份指纹与规范化目录键；非 Codex 账号的 code 为 None，不制造 A–H 映射。通用外部 CLI 命令入口尚未上线时，应复用已审查的 Registry.reserve/update 和有界运行器，不假称 Codex reserve 命令已支持任意提供商。

## 订阅与点数

沿用主 Skill 的点数保护：Grok 按官方订阅窗口判断，耗尽后不自动使用点数、API Key 或付费回退；字段缺失不通过付费请求探测。单次重置必须满足当前用户明确条件与次数，不扩展到 Codex。

## 非交互执行

正式文件任务前，先按主 Skill 做最小返回验证。1.0.25 已实测 `--tools '' --no-subagents --disable-web-search --max-turns 1 --single` 可用于只返回随机标记的一次请求；实际运行事件确认过一次 `grok-4.6-build` 模型调用、零工具调用与完全匹配的返回。只记录本次随机标记摘要；不能将这次结果当成其他版本、账号或未来任务的自动证明。

Grok 用量查询按官方 billing 实现发送必要客户端模式及当前身份请求头；在本次原生账号请求中，补齐后重新取得了订阅百分比。字段缺失保持未知，不能照搬第三方缺失填零的做法；百分比取整也不能用来判断短任务是否执行。

1. 明确本批文件归属、允许工具和验收产物。准备后登记共享占用，启动时记录实际可执行路径、版本、模型、PID 及进程出生时间。任务正文和工具原始输出不进入公共日志。
2. `--prompt-file` 配合 `--output-format streaming-json` 可产出事件流。当前 1.0.25 的实测中，`--permission-mode acceptEdits` 在关闭 stdin 后仍可能把编辑确认取消，最终退出 0 却没有文件；先查工具完成状态和产物，不盲目重跑。
3. 用户已明确授权本批文件修改时，可将本次运行限定为 `--tools read_file,search_replace,grep,list_dir,todo_write`，再使用该版本支持的 `--always-approve`，并配合 `--no-subagents --disable-web-search`。这个组合只适合限定的文件任务；不能在开放终端、网络或任意工具时照搬，也不写入全局配置。没有编辑授权时不能自动批准。
4. 需要终端、网络、测试或其他工具时单独核对该项任务能力与授权，再选择对应的受控运行方式。不要让不能运行 shell 的任务承担编译或计算哈希；父执行端承担这些验收。
5. 运行器需有总期限、有界输出、心跳、进程组归属校验和结束回执。只保存事件种类、工具状态、退出原因和产物信息；取消/超时只处理本任务拥有的进程。
6. 工具被取消、没有目标产物或验收不符，均不能标记 accepted。记录失败原因，修正有证据的参数问题后再开始新的尝试。同一账号的新一批任务等待当前批次自然结束和收取结果。

## 收取结果与更新

- 核对实际改动文件与启动基线，保留其他人的修改。编译、合成测试、实际 UI、实际安装及服务商返回分别记录。
- 长任务分成能独立验收的小批次。不要让一个简单界面改动重新遍历全仓库、所有 Skill 和历史；父执行端已做的研究写成精简输入。
- 其他任务正在运行时，文档和触发词可独立更新；运行脚本或接口变化先评估兼容性，不能直接改变在途参数。已加载旧 Skill 的任务不宣称自动获得新版规则。
