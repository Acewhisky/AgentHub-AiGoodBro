# 单次派单 brief

下列正文单独复制并填写。以本次授权为准，不把模板中的动作当成额外授权。

```text
任务：<具体问题和完成后的行为>
执行端：<账号编号/alias、Hub 或 direct、已核实的工具>
在线占用：<leaseId、ownerThreadId、当前阶段；子任务不得自行换账号、重复占用或释放其他任务>
参数：<实际模型、推理强度、速度；是否允许子任务>
目录与输入：<真实工作目录、必须读取的文件与现有产物>
负责范围：<允许修改的文件或模块；需保留的功能与脏改动>
协作：你不是唯一工作者，不撤销他人修改；发现写入冲突先报告并完成不冲突的部分。
执行授权：<当前允许的写入、必要修复、测试及已明确授权的上线步骤>
限制：<当前未授权的登录、切号、进程操作、发布/推送、付费、外部发送及其他排除项>
验收：<具体通过标准、适用检查与必须交付的文件；UI/真实服务需何种证据>
断点：<复用的项目进度文件；每完成一个可验收成果记录实际验证、下一步与阻塞>
能力不足：<可独立完成的环节、停在哪一步、交给哪个执行端>
问题记录：所有问题追加主 Skill 的 operations-issues-v1.jsonl；沿用 issueId、自动写上海日期，不复制凭据、邮箱、私人路径或任务正文。
时间：记录实际执行结束时间；编排者记录收取时间，延迟需写原因。
回执：列出改动文件及目的、实际运行的验证、通过/失败/未验收项、产物位置与下一执行端。
Hub 任务提供 resultNote；直跑在最终回复给出回执。不能用退出码 0 代替完成。
```
