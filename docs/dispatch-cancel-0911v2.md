# 取消与超时处理 · 0911v3

相较 0911v2，补齐 Hub 状态同步、子进程有界输出、超时进程身份复核和公开能力目录。

## 取消状态

`cancel_requested` 保留取消意图，只允许心跳/元数据更新、重复取消或经存活检查后的 `cancelled`。新的 starting、running、awaiting_acceptance 或 uncertain 不能覆盖它。取消终态不能再改成 accepted/rejected。

经过身份核对的 Hub 同步在同一把状态锁内处理：Hub 仍活跃时保留取消意图，Hub 已确认终态时允许本地以 cancelled 释放占用；Hub 自己的实际任务结局仍保留在 Hub。未经核对的本地 finish 不获得额外权限。

## 进程与结果

- supervisor 把 claim 放入异常处理内；只有实际取得租约的实例才能处理自己的后续失败。
- 启动后遇到取消仍记录子进程出生标识，保留监督。子进程及同组后代未确认退出时，占用继续保留。
- WorkBuddy 超时和手动取消都核对进程出生标识及进程组。PID 已复用时拒绝发信号，记录超时停止被拒，保留原始退出码与部分输出。
- stdout/stderr 持续排空，保留内容有字节上限；超时、截断或取消的结果不能成为执行成功。
- 已安装、已认证、额度已知、调用成功和验收通过分别表达。回执文件的存在和大小只属于文件清单，不能证明调用。

## 验证

89 项离线调度回归通过，包含取消竞态、Hub 活跃/终态组合、PID 复用、超时、失败结果、模型参数和环境隔离。共享状态的 Swift/Python 互通验证通过。未为此启动真实模型、切号或触发真实重置与通知。
