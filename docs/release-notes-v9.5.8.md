# Codex Account Manager Next v9.5.8

Release name: 0908v3

## Highlights

- 相比 0908v2，不参与调度的账号继续刷新额度与会员日期，5 小时、7 天暖号只受全局开关及原有身份、额度、空闲检查控制；调度编号被移除时，用现有 Hub 账号目录核验身份，不改变参与设置。
- 相比 0908v1，过期会员日期默认在启动及额度维护后重查。先由官方 Codex 刷新该隔离账号的凭证，再读取会员日期；中枢身份及映射不明、额度不新鲜或 Hub 状态未确认的账号不触发凭证更新。
- 会员重查失败至少间隔 15 分钟再试，官方日期仍旧时 6 小时后再查；界面区分待刷新、刷新失败与已核查未更新。迟到的旧资料不覆盖新日期。
- 相比 0907v3，5 小时与 7 天官方额度到期后默认刷新，独立于暖号开关、调度参与和剩余额度；电脑休眠错过的到期检查会在恢复后补做。
- 到期读取失败或仍返回旧的耗尽窗口时，至少间隔 60 秒再次检查；额度读取失败后不使用旧快照触发暖号。
- 首次安装默认开启 5 小时和 7 天暖号。升级保留已有选择，兼容旧版未保存的默认关闭状态。
- 官方登录失效保留脱敏分类，界面能够给出重新登录指引；重试记录随账号删除或应用退出而清理。

## Validation

- macOS arm64 优化构建、严格签名与 5 项运行时资源比对通过，版本为 `9.5.8 (22) / 0908v3`。
- 最终二进制 26 项自检全部通过，包含调度排除后双窗口暖号、会员重查退避和持久化、Hub 缺失任务列表阻断。69 项调度同步离线测试通过。
- 全量 Swift 格式、macOS 兼容性、全局内存风险门禁及差异检查通过。
- 正常退出旧实例后覆盖原安装位置并启动；进程、版本与二进制比对确认只有一个 Next 实例。两项暖号开关保留开启，监控账号仍不参与调度且额度刷新成功。
- 原生界面已显示更新后的参与调度说明，非调度账号不再显示 5 小时暖号被排除。真实到期后的暖号请求仍待对应官方窗口到期验证。

## Runtime acceptance boundaries

- 此版本完成本机覆盖安装并用于 GitHub 源码及资料更新；不创建 Git 标签、GitHub Release 或上传安装包。
- 新增到期规则以隔离测试覆盖；真实 7 天窗口到期仍取决于官方时间及服务响应。
- 暖号继续执行身份、额度及任务空闲检查；不改写当前 Codex Desktop 身份。
