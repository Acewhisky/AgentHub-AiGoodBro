# Codex Account Manager Next v9.5.13

Release name: 0909v2

## Changes from 0909v1

- 飞书通知前读取钥匙串曾使主线程持续等待，连带停止界面、额度刷新和自动暖号。配置检查与通知读取均移至独立后台队列。
- 读取 5 秒后报告超时，最多保留 16 项等待读取；已超时的排队操作直接跳过，系统迟到的结果被丢弃，避免恢复后补发旧通知。
- 发送前重新核对用户的通知开关、事件选择和配置版本。异步配置检查也不会覆盖用户之后保存或移除的配置状态。
- 继承 0909v1 的持续暖号、失败重试及退出调度保留编号。账号维护不等待飞书通知完成。

## Validation

- macOS `9.5.13 (27) / 0909v2` 已完成 26 组应用自检、格式、兼容、资源和严格签名验证，并于 09-09 08:38 在原路径覆盖运行；旧版 ZIP 已校验保留，单实例及实际二进制与最终候选一致。
- 隔离回归模拟长期钥匙串等待，验证主线程仍能执行、读取超时、积压上限、恢复后丢弃迟到结果、正常发送及关闭后取消。模拟传输拦截全部请求，无真实钥匙串读取或通知发送。
- 安装后的多个自动额度刷新周期继续推进，主界面可读取且识别飞书配置；账号参与设置、两项暖号和系统认证/配置文件元数据均保持。下一轮自然暖号仍需到点验收。

## Runtime boundaries

- 超时结束的是应用等待；系统钥匙串调用本身无法在这里取消。因此保留后台队列和上限，防止继续积压，也不修改系统钥匙串或认证策略。
- 本轮不以测试通过证明真实通知送达或完整 7 天自然暖号周期。后续自动暖号须依据新请求、新鲜额度与官方 reset 的实际推进验收。
- 自动化中心面板的原生控制通道中断，面板验收未完成；当时 Next 主线程处于正常事件循环，额度刷新继续。
- 未创建标签、推送、发布安装包、制作 DMG 或执行 notarization。
